# 节点心跳接收端（开发候选，尚未部署）

本轮实现独立 `server/cmd/node-api`。它只接收持有有效证书的节点心跳，将最后上报时间、程序版本、连接数和负载写入数据库，既有后台节点列表读取这些字段。它不启动 VPN 内核，不下发用户凭据，不计费，也不触发任何付款。

第十六轮已接入 `node-agent` 的证书客户端、私有状态持久化、防双开、心跳发送与Linux系统指标采集；真实在线连接数/已应用配置仍需内核适配器提供状态文件，见 `节点agent状态文件契约.md`。自动签发/续期、配置拉取、用户快照/事件、流量上报和真实隧道仍未接通。不能仅凭心跳新鲜就认定 VPN 可连接或设备撤销已执行。后台的 `sync_status=UNAVAILABLE` 保持不变。

## 身份与监听

- 使用独立进程、独立数据库登录和专用节点 CA。App 主进程未增加监听口，不需要提供 App 签名密钥、加密密钥或钱包配置。
- `NODE_API_ENABLED` 默认 `false`，只接受小写 `true`/`false`。开启时还须填写 `NODE_DATABASE_URL`、明确的 `NODE_API_LISTEN` IP/端口和三个 TLS 文件绝对路径。示例默认回环 `127.0.0.1:18443`，不会自动对公网开放。
- `NODE_TLS_SERVER_CERT` 与 `NODE_TLS_SERVER_KEY` 是服务端 TLS 证书与私钥；证书须有 ServerAuth 用途和 DNS/IP SAN。私钥仅留部署机器，限制读取权限。测试证书由测试临时生成，未提供生产默认密钥。
- `NODE_TLS_CLIENT_CA` 只允许有效 CA 证书 PEM，不能使用公共系统根库代替节点专用信任根。TLS 最低 1.3，强制客户端证书认证，没有明文或转发头回退。
- 客户端证书必须显式含 ClientAuth 用途、非 CA、唯一 URI SAN `spiffe://yuhai.internal/node/<节点ID>`；ID 是不含前导零的正 int64 十进制数。不采用 CN 回退。
- 节点表须预先存在，并由部署人员登记该证书完整 DER 的小写 SHA-256 到 `agent_cert_fingerprint`。节点禁用、指纹置空或替换后，原证书的后续请求均被拒绝，包含同一 TLS 长连接。
- 每次请求及事务锁定后重新验证证书链和有效期；提交前再次验证证书有效性。支持根 CA 信任文件重启更新，尚无自动 CRL/OCSP/CA 热更新，不能声称实现了完整证书生命周期。

实现依据 Go 官方 [TLS 服务端客户端证书验证](https://pkg.go.dev/crypto/tls#Config) 和 [X.509 证书链验证](https://pkg.go.dev/crypto/x509#Certificate.Verify)，另外使用数据库指纹验证节点当前授权。

## 请求与防重复

完整契约在 `api/openapi/node.yaml`，最新版本 1.3.0。只开放 `POST /node/v1/heartbeat`，其他控制面路由尚未实现。JSON 最多 4096 字节，拒绝重复/未知字段、缺失必需项、null、查询参数、压缩请求体和非 JSON 类型。

`sequence` 是每节点持久单调递增的正 int64 字符串。发送方必须先持久化序号和规范化请求，进程重启、丢失响应或换证都不能把序号归零。最新相同序号相同内容返回原接收时间且 `duplicate=true`，不刷新心跳时间；相同序号不同内容、较旧序号返回 40901。序号可以跳跃，但不能超过 int64 上限。当前每节点只存最新回执；更旧请求返回冲突，不提供完整历史回放。

新序号要求 `sent_at` 是带 Z 的 UTC 时间，最多六位小数秒，在服务器当前时间前 60 秒至后 5 秒以内，且不得早于上一份上报。正常每 30 秒一次；不足 5 秒的新序号返回 42901。重复最新序号只读核实，不因时间超窗变成新写入。节点禁用/换证检查仍先于重复回执返回。

心跳和幂等回执在同一事务提交；锁定节点行，将并发上报与节点禁用/指纹变更排序。请求事务最多 5 秒，HTTP 读写各最多 10 秒。写入失败会回滚两处数据。客户端遇到不确定结果，不得自行重置序号或换内容“重试”；应保留原请求并核实最新回执。

CPU/内存用 0–100 的向上取整百分比，连接数 0–10000000；带宽与配置版本是非负 int64 字符串。当前负载取 CPU 与连接数/配置容量百分比的较大值，上限 100。尚无链路带宽容量配置，因此不计算带宽利用率。`config_version=0`、空 checksum 代表未应用配置；其他上报值同样只是节点自报，不是中央验证的执行证明。

心跳绝不把 MAINTENANCE/OFFLINE 改为 ONLINE，也不会恢复 DISABLED。管理员配置状态与心跳新鲜程度是两项独立信息。第十六轮App列表已移除MOCK回退，要求新鲜心跳、回执证书与当前指纹一致、有已应用配置/快照及启用入站，才作为候选显示；实际隧道连接仍需独立核验。

## 部署前条件（本轮未执行）

1. 完成身份校验代码的独立评审，再进行生产部署；本轮只有测试与自查，不代替双人评审。
2. 备份目标数据库，由迁移角色执行 `00018_node_heartbeats.sql`、`00019_node_heartbeat_identity.sql` 和 `00020_node_ready_protocols.sql`。不能把本机隔离测试当成正式迁移。生产回滚代码时保留心跳序号表，不回滚或清空防重水位。
3. 为新进程创建独立登录，授予业务 schema 的 USAGE、nodes 的 SELECT、节点遥测五列的 UPDATE，以及 node_heartbeats 的 SELECT/INSERT/UPDATE。无需节点配置 UPDATE、DELETE、凭据、管理员或资金表权限。示意授权如下，角色必须由运维预先建立，代码不会创建账号或密码：

```sql
GRANT USAGE ON SCHEMA public TO yuhai_node_runtime;
GRANT SELECT ON public.nodes TO yuhai_node_runtime;
GRANT UPDATE (agent_version, online_count, load_score, last_heartbeat_at, updated_at)
  ON public.nodes TO yuhai_node_runtime;
GRANT SELECT, INSERT, UPDATE ON public.node_heartbeats TO yuhai_node_runtime;
```

4. 提供可信服务端证书、专用客户端 CA、经过授权的节点记录及证书指纹。尚未实现自动 enroll，不能用伪造生产节点或示例私钥填补此步骤。
5. 使用独立进程管理器运行 `node-api`；防火墙限制为节点出口 IP。证书在本进程终止 TLS；不得通过普通 HTTP 反向代理转发证书头模拟 mTLS。
6. 节点端持久化和系统指标采集已实现；接入真实内核运行状态来源后，做受控实节点心跳测试、证书轮换和数据库备份恢复演练。心跳成功不等于全套 VPN 交付。

## 验证范围

本轮测试使用本机 15432 隔离 PostgreSQL、每次随机 schema、最小表权限，以及临时生成的 CA/客户端/服务端证书；HTTP 测试实际进行双向 TLS 握手。未调用真实节点、生产数据库、生产钱包或现有闪兑程序。

第十七轮：心跳新增ready_protocols，缺失为空；仅该集合与启用入站的交集能进入App候选。旧回执迁移后不会自动具备协议就绪信息。WireGuard节点有独立只读观察器，核对实际公钥、监听端口、peer允许地址与清单是否一致；输入清单的控制面同步、内核配置写入仍未实现。投影校验值不是全协议用户快照回执。
