# 节点 agent 状态文件契约（开发候选）

Linux节点上报程序只读取系统指标和内核适配器提供的运行状态，不执行命令，不启动VPN，不修改路由或防火墙。第十七轮增加独立WireGuard只读核对程序node-runtime；Xray生产者仍未实现。不能把填写清单当成VPN已运行，详见WireGuard运行核对契约.md。

`NODE_AGENT_ENABLED=false`默认关闭。运行需明确设置HTTPS控制面原点、客户端证书/私钥、服务端信任CA、状态目录、网卡名称和运行状态文件路径。URL不得含账户、路径、查询、片段；客户端不使用环境代理、不跟随重定向。

`NODE_RUNTIME_STATUS_FILE`由运行核对程序原子替换更新，归节点程序用户所有、权限0600、禁止符号链接。最多4096字节，拒绝重复/未知/null/缺失字段。

| 字段 | 约束 |
| --- | --- |
| schema | 固定2，旧版缺就绪协议的状态文件不再通过 |
| node_id | 与客户端证书URI的正int64字符串一致 |
| observed_at | UTC Z时间，最多6位小数；读取时不得未来或超过10秒 |
| config_version | 已实际应用配置版本，正int64字符串 |
| snapshot_checksum | 已核对公开用户投影的64位小写SHA256；WireGuard当前按运行核对契约计算，不等于完整控制面快照校验 |
| online_count | 0至10000000；WireGuard表示最近180秒有握手的活跃peer估计，不是TCP连接数/计费凭据 |
| ready_protocols | 非空、至多5个互不重复的规范协议；当前观察器只报告WIREGUARD |

版本0、空校验值或臆造0连接不能替代缺失适配器；实际核对成功的空peer列表可以报告0。缺文件/过期/错误身份都跳过新采样。已有待确认请求仍原样核实，其重复回执不会刷新服务端心跳。

CPU从Linux`/proc/stat`两次采样（约1秒）的前8项计算，不重复计入guest；内存使用`MemTotal-MemAvailable`占比，百分比向上取整。带宽仅采集明确指定网卡的字节增量，换算比特/秒，并非VPN计费流量。计数倒退、无有效间隔、超限或缺指标时拒绝该样本。指标依据[Linux官方proc文档](https://docs.kernel.org/filesystems/proc.html)。

`node-agent init-state`仅可初始化从未存在的目录。普通启动必须读取完整状态；丢失/损坏则停止，不能自动归零。目录0700、文件0600；操作系统文件锁防同目录双开。状态更新先同步临时文件、替换，再同步目录。状态绑定节点身份与控制面URL。不同机器复制目录不共享锁，因此每个节点仍须只保留一个授权实例。

常驻约30秒一步。发送前持久化完整请求和序号；断线/5xx/429保留原请求，下个周期原样重试。严格匹配成功回执才清除pending；明确40105可放弃过期请求，保留序号水位，下一周期用更高序号重新采样。其他400/401/403/409、错误回执或证书问题停止并保留现场，不删状态或回退序号。

停止/失败后运行文件至多10秒失效，控制面既有心跳候选另有90秒窗口；不声称立即将现有用户断线。真实Linux采集仍需目标机器验收。当前未部署、无生产证书；不修改TRON网站或闪兑进程。
