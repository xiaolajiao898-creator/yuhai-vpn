# 宇海加密VPN · 单体仓库

高端、稳定、简洁、私密的跨平台加密 VPN。设计方案见 `docs/系统设计方案_v1.0.md`，本仓库结构与方案第 2.2 节一致。

```
yuhai-vpn/
├── api/openapi/          # 契约先行：app.yaml / node.yaml / admin.yaml（OpenAPI 3.1）
├── server/               # Go 模块化单体：api / admin-api / worker / node-agent 四个二进制
│   ├── cmd/              # 各二进制入口
│   ├── internal/         # 业务模块（包边界 = 模块边界，模块间只通过接口调用）
│   │   └── db/migrations # goose 迁移，来源于方案第 10 章 DDL
│   └── scripts/          # 数据库角色、本地初始化
├── apps/mobile/          # Flutter 客户端（Riverpod / go_router / dio）
├── apps/admin-web/       # React + Ant Design 管理后台
├── apps/website/         # Astro 官网、下载页、邀请落地页
├── deploy/               # docker-compose 本地环境、CI
└── docs/                 # 设计文档
```

## 本地开发

```bash
cp .env.example .env
make up          # PostgreSQL 17 + Redis
make migrate     # goose 迁移
make sqlc        # 由 internal/db/queries/*.sql 生成类型安全的 Go 代码
make gen         # 由 OpenAPI 契约生成 Go 服务端桩与 Dart 客户端
make run-api     # http://localhost:8080
make run-admin   # http://localhost:8081（开发工具路由仅在 APP_ENV != production 时注册）
make run-worker
```

移动端：

```bash
cd apps/mobile
flutter create . --org com.yuhai --project-name yuhai_vpn   # 生成 android/ ios/ 原生工程（只需一次）
flutter pub get && flutter run
```

## 铁律（来自方案第 0、6、10、12 章）

1. 金额在数据库与业务代码中一律为 micro-USDT 整数（`int64`），接口层为字符串；禁止浮点。
2. 所有写操作携带确定性幂等键；到账、开通、奖励在同一事务内完成，重复触发不得重复入账。
3. 业务服务只用 `yuhai_app` / `yuhai_admin` 角色连接数据库，绝不使用表所有者角色。
4. 生产环境启动时若发现 `MOCK` 网络收款地址或开发开关，服务必须拒绝启动。
5. 涉及资金、权益、认证的改动强制双人评审。

```bash

cd apps/admin-web && npm i && npm run gen
```

本轮新增 peer 实际下发能力，由 `NODE_WG_APPLY_ENABLED` 控制，**默认 false**。关闭时同步只落盘、
不碰内核。`wg show` 的输出格式与 `SetPeers` 拼出的 argv 已用真实 wireguard-tools 验证通过；
`listen-port` 一项尚未在内核模块节点上坐实。上线前在目标节点执行：

```bash
go run ./cmd/wgcheck -wg /usr/bin/wg -iface wg0   # 只读复核，全绿后才考虑打开开关
```

本轮另新增连接材料签发 `POST /v1/connect/profiles`（无开关，随 api 启用）：只下发**本设备自己的**
WireGuard 材料，凭据按 `device_id` 精确取；节点门槛与 App 节点列表同一套；权益不足给明确错误码
（40301/40303/40305/40107），请求的节点全部不可用整体 50302，不退化成返回空列表；只实现 WIREGUARD，
其余协议按 `PROTOCOL_UNSUPPORTED` 返回，绝不编造字段。详见 `HANDOFF-ROUND18.md` 第 10 节。

同时补上了 `PUT /v1/devices/current/wg-key`：此前**没有任何代码**会写 `device_credentials.wg_pubkey`
与 `wg_address`，控制面清单因此永远是空的。现在设备上传公钥即分配隧道地址（公钥与地址同一条
UPDATE 写入，不留半截记录），公钥全局唯一、抢占返回 40901，轮换不换地址，地址**永不回收**。
地址池 `WG_ADDRESS_POOL` 在启动期校验必须是私有网段（/12–/28），耗尽返回新错误码 50304。
详见 `HANDOFF-ROUND18.md` 第 11 节。

并新增契约一致性守卫（`cmd/api/routes_test.go`、`cmd/admin-api/routes_test.go`）：契约里有而路由没挂，
或路由挂了而契约里没有，都会让测试变红；未实现的接口必须**明示**写进 `pendingApp` / `pendingAdmin`。
这两张表就是当前真实的缺口清单——App 侧 3 个未实现 + 1 个占位，**后台侧 41 个未实现**。
另新增端到端接缝测试，断言客户端拿到的材料与节点被告知的 peer 逐字节一致（`wireguard_endtoend_test.go`）。

本轮还补齐了后台节点管理写接口（00023：`node-groups` 增查、`nodes` 增改、`inbounds` 增查）——
在此之前节点只能靠手写 SQL 插进库。这些接口**只改登记信息，从不联系任何机器**；
`agent_cert_fingerprint` 不可写入，新建节点恒为 MAINTENANCE、新建入站默认 DISABLED；
入站参数用与节点侧同一份实现严格校验，建不出一条会让整台节点资料无效的入站。
`nodes.write` 独立于 `nodes.read`，迁移只定义不授予。详见 `HANDOFF-ROUND18.md` 第 13 节。

并打通节点注册（00024，`NODE_ENROLL_ENABLED` 默认 false）：后台签发一次性令牌（只显示一次、
不可重放、同节点同时只有一把），节点用 CSR 换客户端证书——**CSR 里除公钥外一概不信**，
身份只由令牌决定；签完自检必须能通过本控制面自己的校验才发出去；令牌一次性，并发只成功一次。
另有 `POST /nodes/{id}/revoke` 解除绑定并下线（**不断开已有隧道**）。详见 `HANDOFF-ROUND18.md` 第 14 节。

并补上证书续期与节点自取配置（00025）：续期要求过了证书寿命 2/3，换绑时保留 24 小时重叠窗口
——没有它，「续期成功但响应丢了」会让节点永久失联；`GET /node/v1/config` 只下发 ENABLED 入站，
不含任何用户凭证。`/users/snapshot` 与 `/users/events` **刻意不做**：它们要求下发 proxy_secret 明文，
而 node-api 进程不加载字段加密密钥，为没有消费方的功能破坏这道隔离不划算（理由已写进契约）。
详见 `HANDOFF-ROUND18.md` 第 15 节。

并补齐资金只读六个接口（00026，新能力 finance.read）：订单列表/详情、链上转账、到账异常、
收款地址、扫描游标。金额一律字符串（固定 6 位小数），链上原始载荷与地址签名原文一律不返回，
扫描游标只如实呈现、不替人判断「是否落后」。详见 `HANDOFF-ROUND18.md` 第 16 节。

并补齐风控处置四个接口（00027）：黑名单增删查与账户状态变更。**黑名单当前只在邀请链路生效**
（只有 invite 的绑定与奖励会读它），因此 effects 只接受代码真正会检查的三个值；解除是留痕不是删除；
账户三个状态效果各不相同，且都不会立即切断已建立的隧道。详见 `HANDOFF-ROUND18.md` 第 17 节。

并补齐邀请复核三个接口（00028）：邀请关系与奖励列表、奖励复核放行/驳回。**这解开的是一个死结**——
被风控挂起的奖励会停在 REVIEW，而 worker 只处理 PENDING，此前既看不见也没人能处置。
复核不重跑风控（否则死循环），但完整性检查一条不省，任一条不成立整笔回滚并返回原因码。
放行会当场记账，因此 admin-api 从这一轮起具备写账能力。详见 `HANDOFF-ROUND18.md` 第 18 节。

并补齐套餐管理四个接口（00029）：列表（含草稿与已下架）、新建、修改、上下架。
**这组的要害是 version**——未结报价记着下单时的 plan_version，下单时比对，不一致就要求重新报价。
因此实质字段（价格、时长、配额、设备数等）改动必须 +1，外观字段（名称、角标、排序）不许动它；
测试直接用 plan.LockQuote 验证「改价之后那张报价真的下不了单」，并做过变异测试。
契约按数据库改正三处：删掉全库不存在的 node_group_ids、状态枚举去掉 HIDDEN、
配额字段按类型拆开。详见 `HANDOFF-ROUND18.md` 第 19 节。

生产部署、独立双人评审。节点注册与续期链路**未在真实机器上跑过**，开关保持关闭。
